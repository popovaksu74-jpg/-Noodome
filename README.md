# Noôdome · Приглашения

Сервис для команды клуба Noôdome: из интервью об участнике он собирает именную страницу-приглашение, которую участник отправляет знакомым.

> Это учебный проект. Тексты, фото и афиша взяты с noodome.club и из презентации клуба как пример; источники перечислены в конце. Пример Михаила Тихомирова публикуется с его слов из открытого интервью. Перед реальным использованием нужно согласие каждого участника.

## О проекте

### Задача
Клуб растёт по рекомендациям участников («Коннекторов»). Успех измеряется количеством заявок кандидатов. Универсальная страница клуба не работает так же, как личное приглашение от знакомого человека. Но делать страницу для каждого участника вручную дорого: нужно прочитать интервью, выбрать главное, написать тексты, вёрстать, согласовать.

### Решение
Сервис, который берёт интервью или заметки и превращает их в готовую страницу-приглашение за несколько минут. Команда клуба проверяет текст, согласует его с участником и публикует.

Главная идея: **у человека меняются только три блока, остальное общее для всех.**

| Свой у каждого участника | Общий для всех приглашений |
|---|---|
| Обложка: «{Имя} приглашает вас познакомиться с Noôdome» | Что такое Noôdome |
| «Для меня Noôdome»: один абзац и фото | Сообщество: цифры и амбассадоры |
| «Что мне здесь близко»: три пункта | Чем живёт клуб: афиша |
| «Мой проект с Noôdome»: текст, фото, ссылка | Как проходит знакомство, форма заявки, подвал как на сайте клуба |

Общие блоки правятся в одном месте («Клуб: общие блоки») и меняются во всех приглашениях сразу. Поэтому афишу, амбассадоров и тексты о клубе не нужно переписывать для каждого человека.

### Для кого
- **Команда клуба.** Создаёт и правит приглашения. Для неё сервис.
- **Участник-Коннектор.** Согласует свою страницу и отправляет ссылку знакомым.
- **Кандидат.** Открывает страницу на телефоне, читает, оставляет заявку.

### Что умеет
1. **Создание из материалов.** Загрузка .docx, .pdf, .txt или вставка текста. ИИ выписывает факты, помечает, что процитировано, что пересказано, что выведено, и пишет три блока.
2. **Проверка фактов.** Вкладка «Проверка»: откуда взят каждый блок, какие вопросы нужно уточнить у участника. Что не берём на страницу (финансы, здоровье, политика), записывается отдельно.
3. **Редактор блоков.** Порядок, дублирование, удаление, фон, фото. Живое превью на телефоне и компьютере.
4. **ИИ внутри сервиса.** Кнопки «Сгенерировать» и «Переписать» работают по ключу сотрудника. Есть запасной путь через чат claude.ai.
5. **Общие блоки клуба.** Один раздел для афиши, амбассадоров, текстов о клубе.
6. **Согласование.** Статусы «Черновик» и «Согласовано». При скачивании черновика сервис предупреждает, что текст нужно согласовать с участником. Это правило процесса, технически публикацию он не блокирует.
7. **Готовая страница одним файлом.** Скачивается и размещается на любом хостинге. Форма заявки без сервера отдаёт кандидату готовый текст для отправки клубу, а при подключённом приёмнике отправляет заявку сама.
8. **Работа без аккаунтов и сервера.** Всё хранится в браузере, резервная копия сохраняется в файл.

### Как устроено
- **Один HTML-файл** (`index.html`) на чистом JavaScript, без фреймворков и сборки на стороне пользователя. Размещается на GitHub Pages бесплатно.
- **Один движок вёрстки** (`src/landing.js`) используется и для превью в редакторе, и для итоговой страницы. Страница, которую видит кандидат, совпадает с превью.
- **Блоки как данные.** Страница это список блоков `{тип, данные}`. Новый тип блока добавляется описанием полей, редактор строится по нему сам.
- **Ключ ИИ только в браузере сотрудника.** Репозиторий публичный, поэтому ключ нельзя хранить в коде. Он не попадает ни в резервный файл, ни в готовую страницу.
- **Подвал и стиль как на noodome.club:** палитра, шрифт Cormorant Garamond (вместо фирменного Wremena), логотип-купол, чёрный подвал с крупной надписью.

### Принятые решения и почему
- **Три блока на человека, остальное общее.** Так страница остаётся личной, а редактировать её быстро. Команда клуба обсудит оставшиеся блоки отдельно.
- **Согласование перед публикацией.** Слова и фото человека должны публиковаться только с его согласия: для этого есть статус, вкладка «Проверка» и предупреждение при скачивании. Сервис не обрабатывает персональные данные кандидатов сам: заявка уходит в команду клуба.
- **Без сервера.** Не нужно хостить и защищать базу. Цена: данные живут в браузере, обмен между сотрудниками идёт через файл.
- **Ничего не выдумывать.** ИИ получает правила: цитаты только дословные, факты только из материалов, нет данных, значит вопрос в «Проверку».

### Ограничения
- Данные хранятся в браузере каждого сотрудника, общего хранилища нет.
- Заявки без приёмника уходят по почте вручную: кандидат копирует готовый текст.
- Опубликованные страницы не обновляются сами: после правки общих блоков их нужно скачать заново.
- Бесплатные тарифы ИИ имеют лимиты и могут использовать тексты для обучения моделей.
- Фото к проекту Михаила взято из открытых источников; кадры с самого «Восхода» нужно запросить у него.

### Что дальше
- Общее хранилище и учётные записи для команды.
- Приёмник заявок, воронка и статусы кандидатов.
- Автоматическая подборка актуальных мероприятий под кандидата.
- Версии и история правок, комментарии участника прямо на странице.

## Демонстрация за 5 минут

Ключ ИИ не нужен.

1. **Результат (1 мин).** Откройте `i/mikhail-tikhomirov.html` с телефона или в узком окне. Пролистайте: обложка с дугой, «Для меня Noôdome», проект «Восход (пре)красный», блоки клуба, форма, подвал.
2. **Сервис (30 с).** Откройте главную страницу. В списке виден пример Михаила и статус «Черновик».
3. **Новое приглашение (2 мин).**
   1. Нажмите **Новое** → внизу шага 1 **«Нет материалов? Показать на вымышленном примере»**. Появится интервью вымышленной участницы.
   2. В шаге 3 можно **скопировать запрос** и показать, какие правила получает ИИ (ничего не выдумывать, цитаты дословные, что не берём на страницу).
   3. Нажмите **«Применить готовый ответ»**. Откроется готовая страница.
4. **Редактор (1 мин).** Нажмите блок в превью: откроются его поля. Поменяйте абзац «Для меня Noôdome» и фон, посмотрите превью. Откройте вкладку **«Проверка»**: вопросы к участнику и откуда взят каждый блок.
5. **Общие блоки (30 с).** Слева **«Клуб: общие блоки»**. Поменяйте дату или название мероприятия: оно изменится во всех приглашениях.
6. **Выдача (30 с).** **Согласовано** → **Скачать лендинг**. Откройте файл и отправьте тестовую заявку: появится готовый текст для клуба.
7. **ИИ по ключу (по желанию).** **Подключение ИИ** → вставьте ключ Gemini → **Проверить ключ**. После этого в «Новое» появится кнопка **«Сгенерировать»**, а в блоках «Переписать с Claude».

Пример Елены Соколовой и её проект вымышлены и нужны только для показа. Удалить: открыть приглашение → ⋯ → «Удалить приглашение».

---

- Сервер и ключ API не нужны.
- Тексты пишет ИИ прямо в сервисе по ключу, который каждый сотрудник вводит у себя. Если ключа нет или лимит кончился, запрос можно перенести в чат claude.ai вручную.
- Сайт бесплатно размещается на GitHub Pages.

| `src/data/mikhail-tikhomirov.seed.json` | Пример приглашения, который видит новый пользователь |
| `src/build.py` | Собирает `index.html` из `src/` |

## 1. Залить на GitHub через сайт, без программ

1. Зайдите на [github.com](https://github.com) и войдите. Лучше заведите аккаунт или организацию клуба, а не личный.
2. Справа вверху нажмите **＋ → New repository**:
   - **Repository name**: `noodome-invite`, или любое латиницей. Оно станет частью адреса;
   - **Public**. GitHub Pages бесплатно работает только с публичными репозиториями (подробнее в разделе 5);
   - галочки README и .gitignore не ставьте;
   - **Create repository**.
3. На странице пустого репозитория нажмите ссылку **uploading an existing file**.
4. Откройте эту папку в Finder. Выделите всё **содержимое** (`index.html`, `README.md`, папки `i` и `src`) и перетащите в окно браузера. Перетаскивайте содержимое, а не саму папку.
   - Скрытый файл `.nojekyll` не обязателен. Чтобы увидеть его в Finder, нажмите Cmd+Shift+точка.
5. Внизу нажмите **Commit changes**.
6. Откройте **Settings → Pages** (в меню слева):
   - **Source**: Deploy from a branch;
   - **Branch**: `main`, папка `/ (root)`;
   - **Save**.
7. Через 1–2 минуты вверху страницы Pages появится адрес вида `https://ИМЯ-АККАУНТА.github.io/noodome-invite/`:
   - **сервис для команды**: `https://ИМЯ-АККАУНТА.github.io/noodome-invite/`;
   - **приглашение Михаила**: `https://ИМЯ-АККАУНТА.github.io/noodome-invite/i/mikhail-tikhomirov.html`.

## 2. Подключить ИИ (один раз, каждому сотруднику)

**Ключ нельзя класть в репозиторий.** Репозиторий публичный: любой возьмёт ключ себе, и лимит закончится. Поэтому ключ вводится в сервисе и хранится только в браузере сотрудника. В «Сохранить всё», в скачанные лендинги и на GitHub он не попадает.

1. Откройте сервис и слева выберите **«Подключение ИИ»**.
2. Получите ключ. Самый простой вариант с бесплатным тарифом: **Google Gemini**.
   1. Откройте [aistudio.google.com/apikey](https://aistudio.google.com/apikey) и войдите в свой Google-аккаунт.
   2. Нажмите **Create API key** и скопируйте ключ.
   3. В сервисе выберите «Google Gemini», вставьте ключ и нажмите **«Проверить ключ»**. Должно появиться «Работает».
3. Теперь в блоках «Новое», «Переписать» и «Добавить блок» есть кнопка **«Сгенерировать»**.

Другие варианты в том же списке: Groq и OpenRouter (есть бесплатные тарифы, но лимиты на длину текста меньше) и Claude (платный ключ с console.anthropic.com).

**Предупреждения:**
- Бесплатные тарифы могут использовать присланные тексты для обучения моделей. Интервью содержат личные данные участников. Если это важно, берите платный ключ.
- Ключ не отправляйте в чаты и письма. Если ключ попал не туда, удалите его на странице провайдера и создайте новый.
- Если лимит кончился, подождите минуту. Или нажмите «Или вручную через чат claude.ai» под кнопкой.

## 3. Как опубликовать новое приглашение

1. Откройте сервис по ссылке. Нажмите **Новое**:
   1. загрузите материалы;
   2. скопируйте запрос в Claude;
   3. вставьте ответ;
   4. нажмите **Применить**.
2. Проверьте блоки, вкладку **Проверка** и фото. Согласуйте страницу с участником и нажмите **Согласовано**.
3. Нажмите **Скачать лендинг**. Скачается файл вида `anna-petrova.html`.
4. На GitHub откройте папку `i` → **Add file → Upload files**. Перетащите файл и нажмите **Commit changes**.
5. Через минуту страница откроется по адресу `https://ИМЯ-АККАУНТА.github.io/noodome-invite/i/anna-petrova.html`. Этот адрес подставьте в текст для мессенджера (**⋯ → Текст для мессенджера**).

**Чтобы поправить** опубликованное приглашение, скачайте лендинг заново и загрузите файл с тем же именем: GitHub заменит старый.

**Чтобы убрать** приглашение, откройте файл в папке `i` → **⋯ → Delete file** → Commit.

## 4. Общие блоки и афиша

- Раздел **«Клуб: общие блоки»**. Там меняются:
  - тексты «Что такое Noôdome» и «Сообщество»;
  - амбассадоры и их фото;
  - мероприятия: картинка, дата, рубрика, название, ссылка;
  - шаги и форма.
- Кнопка **«Вернуть исходные»** возвращает тексты и фото по умолчанию из `src/data/club.json`.
- Каждый опубликованный лендинг — отдельный файл со своей копией общих блоков. После правки афиши уже выложенные приглашения сами не обновятся. Скачайте нужные заново и загрузите в `i/`.
- В афише сейчас стоят 5 мероприятий ноября 2026 с noodome.club/events. Это пример. Актуальные события участнику можно присылать лично.

## 5. Где хранятся данные и как работать вдвоём

- Приглашения, правки общих блоков и ключ ИИ хранятся **в браузере** того, кто работает: на GitHub они не уходят.
- В другом браузере или на другом компьютере будет пусто, кроме примера.
- Чтобы передать работу коллеге или сделать резервную копию, нажмите слева **«Сохранить всё в файл»**. Коллега открывает сервис и нажимает **«Открыть файл»**.
- Удобно, чтобы общие блоки вёл один человек и рассылал команде свежий файл.
- Файл «Сохранить всё» **не кладите в репозиторий**: в нём исходные интервью и заметки для проверки.

## 6. Важно про публичность

- Публичный репозиторий видят все: код, `index.html` (в нём пример Михаила вместе с текстом интервью) и все файлы в `i/`.
  - Кладите в `i/` только согласованные с участником страницы.
  - В скачанный лендинг попадают только тексты и фото самой страницы. Интервью, заметки и вопросы для проверки туда не попадают.
- Страницы закрыты от поисковиков (`noindex`), но открываются у любого, у кого есть ссылка.
- Если репозиторий должен быть закрытым, для Pages нужен платный план GitHub. Сами страницы при этом всё равно открываются по ссылке.

## 7. Заявки кандидатов

Сейчас приёмника заявок нет. Кандидат заполняет форму и получает готовый текст: «Заявка по рекомендации: Михаил Тихомиров…». Он копирует его и отправляет на customers@nd.club.

Когда появится приёмник, например Google Apps Script или форма CRM:

1. Впишите его адрес в редакторе: **Настройки → «Куда отправлять заявки кандидатов»**.
2. Скачайте лендинги заново.

## 8. Свой адрес вместо github.io (по желанию)

1. **Settings → Pages → Custom domain**: например, `invite.noodome.club`.
2. У того, кто управляет DNS домена, добавьте запись `CNAME invite → ИМЯ-АККАУНТА.github.io`.
3. Через 10–30 минут включите **Enforce HTTPS**.

## 9. Если меняете код

1. Правьте файлы в `src/`.
2. Выполните `python3 src/build.py` из корня репозитория. Обновится `index.html`.
3. Загрузите `index.html` и изменённые файлы на GitHub.

Хотите, чтобы у всех обновились общие блоки по умолчанию? Поменяйте `src/data/club.json` и увеличьте в нём `"version"` на 1. Тогда при следующем открытии сервиса общие блоки обновятся у всех. Правки, которые человек сделал у себя в разделе «Клуб», при этом заменятся.
