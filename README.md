# Noôdome · Приглашения

Сервис для команды клуба Noôdome: из интервью об участнике он собирает именную страницу-приглашение, которую участник отправляет знакомым.

> Это учебный проект. Тексты, фото и афиша взяты с noodome.club и из презентации клуба как пример; источники перечислены в конце. Пример Михаила Тихомирова публикуется с его слов из открытого интервью. Перед реальным использованием нужно согласие каждого участника.

2. **Сервис в работе:** [popovaksu74-jpg.github.io/-Noodome](https://popovaksu74-jpg.github.io/-Noodome/). Откройте его, нажмите **Новое → «Нет материалов? Показать на вымышленном примере»** и пройдите сценарий из раздела «Демонстрация за 5 минут». Ключ ИИ и вход не нужны: демо работает в вашем браузере, данные остаются у вас.
3. **Готовое приглашение:** [i/mikhail-tikhomirov.html](https://popovaksu74-jpg.github.io/-Noodome/i/mikhail-tikhomirov.html), пример результата, который видит кандидат.
4. **Код:** папка [`src/`](src/) (интерфейс и вёрстка) и [`backend/Code.gs`](backend/Code.gs) (хранилище и заявки).

Оно описано в разделе «3. Общее хранилище» и показывается на записи экрана или живьём. Тестировалось на имитации сервисов Google, на рабочей таблице пользователя проверка пока не проводилась.

## О проекте

### Задача
Клуб растёт по рекомендациям участников («Коннекторов»). Успех измеряется количеством заявок кандидатов. Универсальная страница клуба не работает так же, как личное приглашение от знакомого человека. Но делать страницу для каждого участника вручную дорого: нужно прочитать интервью, выбрать главное, написать тексты, вёрстать, согласовать.

### Решение
Сервис, который берёт интервью или заметки и превращает их в готовую страницу-приглашение за несколько минут. Команда клуба проверяет текст, согласует его с участником и публикует.

Главная идея: **у человека меняются только три блока, остальное общее для всех.**

| Свой у каждого участника | Общий для всех приглашений |
|---|---|
| Обложка: «{Имя} приглашает вас познакомиться с Noôdome» | Что такое Noôdome |
| «Для меня Noôdome»: один абзац и фото | Сообщество: цифры и амбассадоры |
| «Что мне здесь близко»: три пункта | Чем живёт клуб: афиша |
| «Мой проект с Noôdome»: текст, фото, ссылка | Как проходит знакомство, форма заявки, подвал как на сайте клуба |

Общие блоки правятся в одном месте («Клуб: общие блоки») и меняются во всех приглашениях сразу. Поэтому афишу, амбассадоров и тексты о клубе не нужно переписывать для каждого человека.

### Для кого
- **Команда клуба.** Создаёт и правит приглашения. Для неё сервис.
- **Участник-Коннектор.** Согласует свою страницу и отправляет ссылку знакомым.
- **Кандидат.** Открывает страницу на телефоне, читает, оставляет заявку.

### Что умеет
1. **Создание из материалов.** Загрузка .docx, .pdf, .txt или вставка текста. ИИ выписывает факты, помечает, что процитировано, что пересказано, что выведено, и пишет три блока.
2. **Проверка фактов.** Вкладка «Проверка»: откуда взят каждый блок, какие вопросы нужно уточнить у участника. Что не берём на страницу (финансы, здоровье, политика), записывается отдельно.
3. **Редактор блоков.** Порядок, дублирование, удаление, фон, фото. Живое превью на телефоне и компьютере.
4. **ИИ внутри сервиса.** Кнопки «Сгенерировать» и «Переписать» работают по ключу сотрудника. Есть запасной путь через чат claude.ai.
5. **Общие блоки клуба.** Один раздел для афиши, амбассадоров, текстов о клубе.
6. **Согласование.** Статусы «Черновик» и «Согласовано». При скачивании черновика сервис предупреждает, что текст нужно согласовать с участником. Это правило процесса, технически публикацию он не блокирует.
7. **Приглашение как ссылка.** Согласованное приглашение открывается по адресу вида `…/p.html?ref=anna-petrova`. Менять файлы на GitHub после каждой правки не нужно: страница берёт данные из общего хранилища. Запасной вариант: «Скачать лендинг» даёт один HTML-файл.
8. **Работа командой.** Приглашения, общие блоки и заявки лежат в Google-таблице владельца. Правки одного сотрудника видят остальные, журнал показывает, кто что сделал, при одновременной правке сервис предупреждает о конфликте.
9. **Заявки в таблицу.** Форма на странице пишет заявку строкой в таблицу. В сервисе у заявки есть статус (Новая, Связались, Встреча, Вступил, Не подошло) и комментарий команды. Позже эту таблицу можно связать с CRM.

### Как устроено
- **Три части.** Сервис для команды (`index.html`), страница-приглашение для кандидата (`p.html`) и хранилище на Google Apps Script (`backend/Code.gs`), привязанное к Google-таблице. Сервис и страница это статические файлы на GitHub Pages на чистом JavaScript, без фреймворков.
- **Один движок вёрстки** (`src/landing.js`) используется и для превью в редакторе, и для итоговой страницы. Страница, которую видит кандидат, совпадает с превью.
- **Блоки как данные.** Страница это список блоков `{тип, данные}`. Новый тип блока добавляется описанием полей, редактор строится по нему сам.
- **Ключ ИИ только в браузере сотрудника.** Репозиторий публичный, поэтому ключ нельзя хранить в коде. Он не попадает ни в резервный файл, ни в готовую страницу.
- **Подвал и стиль как на noodome.club:** палитра, шрифт Cormorant Garamond (вместо фирменного Wremena), логотип-купол, чёрный подвал с крупной надписью.

### Принятые решения и почему
- **Три блока на человека, остальное общее.** Так страница остаётся личной, а редактировать её быстро. Команда клуба обсудит оставшиеся блоки отдельно.
- **Согласование перед публикацией.** Слова и фото человека должны публиковаться только с его согласия: для этого есть статус, вкладка «Проверка» и предупреждение при скачивании. Сервис не обрабатывает персональные данные кандидатов сам: заявка уходит в команду клуба.
- **Без сервера.** Не нужно хостить и защищать базу. Цена: данные живут в браузере, обмен между сотрудниками идёт через файл.
- **Ничего не выдумывать.** ИИ получает правила: цитаты только дословные, факты только из материалов, нет данных, значит вопрос в «Проверку».

### Ограничения
- Синхронизация не мгновенная: сервис сверяется с хранилищем при открытии разделов и раз в 45 секунд. Если двое правят одно приглашение одновременно, второму показывается выбор, чью версию оставить.
- Единый пароль команды вместо личных аккаунтов. Если сотрудник ушёл, пароль нужно сменить.
- Лимиты Google Apps Script (число запросов и время работы в сутки). Для десятков приглашений хватает с большим запасом.
- Превью ссылки в мессенджере общее («Личное приглашение в Noôdome»), без имени участника: у статической страницы нет сервера, который подставил бы имя.
- Бесплатные тарифы ИИ имеют лимиты и могут использовать тексты для обучения моделей.
- Фото к проекту Михаила взято из открытых источников; кадры с самого «Восхода» нужно запросить у него.

### Что дальше
- Связка с CRM: заявки уже лежат в таблице, дальше нужен вебхук или Zapier/Make (см. раздел про хранилище).
- Личные аккаунты сотрудников и права доступа вместо общего пароля.
- Автоматическая подборка актуальных мероприятий под кандидата.
- Комментарии участника прямо на странице, история версий.

## Демонстрация за 5 минут

Ключ ИИ не нужен.

1. **Результат (1 мин).** Откройте `i/mikhail-tikhomirov.html` с телефона или в узком окне. Пролистайте: обложка с дугой, «Для меня Noôdome», проект «Восход (пре)красный», блоки клуба, форма, подвал.
2. **Сервис (30 с).** Откройте главную страницу. В списке виден пример Михаила и статус «Черновик».
3. **Новое приглашение (2 мин).**
   1. Нажмите **Новое** → внизу шага 1 **«Нет материалов? Показать на вымышленном примере»**. Появится интервью вымышленной участницы.
   2. В шаге 3 можно **скопировать запрос** и показать, какие правила получает ИИ (ничего не выдумывать, цитаты дословные, что не берём на страницу).
   3. Нажмите **«Применить готовый ответ»**. Откроется готовая страница.
4. **Редактор (1 мин).** Нажмите блок в превью: откроются его поля. Поменяйте абзац «Для меня Noôdome» и фон, посмотрите превью. Откройте вкладку **«Проверка»**: вопросы к участнику и откуда взят каждый блок.
5. **Общие блоки (30 с).** Слева **«Клуб: общие блоки»**. Поменяйте дату или название мероприятия: оно изменится во всех приглашениях.
6. **Выдача (30 с).** **Согласовано** → **Скачать лендинг**. Откройте файл и отправьте тестовую заявку: появится готовый текст для клуба. Если подключено общее хранилище, вместо файла работает ссылка из «⋯ → Текст для мессенджера», а заявка появляется в разделе **«Заявки»**.
7. **Работа командой (по желанию, нужно подключённое хранилище).** Откройте сервис во втором браузере или в окне инкогнито, подключитесь под другим именем и поправьте приглашение. В первом окне правка появится после обновления, а раздел «Приглашения» покажет, кто что менял. Если править одно и то же в двух окнах одновременно, появится предупреждение о конфликте.
8. **ИИ по ключу (по желанию).** **Подключение ИИ** → вставьте ключ Gemini → **Проверить ключ**. После этого в «Новое» появится кнопка **«Сгенерировать»**, а в блоках «Переписать с Claude».

Пример Елены Соколовой и её проект вымышлены и нужны только для показа. Удалить: открыть приглашение → ⋯ → «Удалить приглашение».

- Приглашения, общие блоки, заявки и журнал действий хранятся в Google-таблице и на Google Диске владельца. Так команда работает вместе, а приглашение открывается по ссылке.

## 2. Подключить ИИ (один раз, каждому сотруднику)

**Ключ нельзя класть в репозиторий.** Репозиторий публичный: любой возьмёт ключ себе, и лимит закончится. Поэтому ключ вводится в сервисе и хранится только в браузере сотрудника. В «Сохранить всё», в скачанные лендинги и на GitHub он не попадает.

1. Откройте сервис и слева выберите **«Подключение ИИ»**.
2. Получите ключ. Самый простой вариант с бесплатным тарифом: **Google Gemini**.
   1. Откройте [aistudio.google.com/apikey](https://aistudio.google.com/apikey) и войдите в свой Google-аккаунт.
   2. Нажмите **Create API key** и скопируйте ключ.
   3. В сервисе выберите «Google Gemini», вставьте ключ и нажмите **«Проверить ключ»**. Должно появиться «Работает».
3. Теперь в блоках «Новое», «Переписать» и «Добавить блок» есть кнопка **«Сгенерировать»**.

Другие варианты в том же списке: Groq и OpenRouter (есть бесплатные тарифы, но лимиты на длину текста меньше) и Claude (платный ключ с console.anthropic.com).

**Предупреждения:**
- Бесплатные тарифы могут использовать присланные тексты для обучения моделей. Интервью содержат личные данные участников. Если это важно, берите платный ключ.
- Ключ не отправляйте в чаты и письма. Если ключ попал не туда, удалите его на странице провайдера и создайте новый.
- Если лимит кончился, подождите минуту. Или нажмите «Или вручную через чат claude.ai» под кнопкой.

## 3. Общее хранилище: Google-таблица (один раз, владелец)

Что это даёт: приглашения и общие блоки хранятся в одном месте, команда видит правки друг друга, приглашение открывается по ссылке, заявки падают в таблицу, а в журнале видно, кто что сделал.

**Шаг 1. Таблица.** Откройте [sheets.new](https://sheets.new), назовите её «Noôdome · Приглашения».

**Шаг 2. Скрипт.**
1. В таблице: **Расширения → Apps Script**. Откроется редактор.
2. Удалите весь код в файле `Код.gs`. Откройте в репозитории `backend/Code.gs`, скопируйте всё и вставьте в редактор. Нажмите **Cmd+S**.

**Шаг 3. Пароль команды.**
1. Слева шестерёнка **«Настройки проекта»** → внизу **«Свойства скрипта»** → **«Добавить свойство скрипта»**.
2. Свойство: `TEAM_TOKEN`, значение: придуманный длинный пароль. Не берите пароли от других сервисов. Сохраните.

**Шаг 4. Подготовка.**
1. Слева вернитесь в **«Редактор»**. Над кодом в списке выберите функцию **`setup`** и нажмите **«Выполнить»**.
2. Google попросит доступ к таблицам и Диску: **«Просмотреть разрешения»** → ваш аккаунт → **«Дополнительно» → «Перейти на страницу (небезопасно)»** → **«Разрешить»**. Предупреждение нормально для ваших собственных скриптов.
3. В нижней панели появится «вкладка … готова» и «папка данных». В таблице появятся вкладки «Заявки», «Приглашения» и «Журнал». Если написано «НЕТ пароля команды», вернитесь к шагу 3.

**Шаг 5. Публикация.**
1. Справа вверху: **Развернуть → Новое развертывание**.
2. Шестерёнка рядом с «Выберите тип» → **«Веб-приложение»**.
3. Описание: `Noôdome`. **Запуск от имени: Я** (ваш аккаунт). **У кого есть доступ: Все**.
4. **Развернуть** и скопируйте **«URL веб-приложения»**. Он оканчивается на `/exec`.

**Шаг 6. Адрес в репозитории.**
1. На GitHub откройте файл `config.json` → значок карандаша.
2. Вставьте адрес: `{ "backend": "https://script.google.com/macros/s/ДЛИННЫЙ-КОД/exec" }`. **Commit changes**.

**Шаг 7. Подключить сервис.**
1. Откройте сервис → слева **«Подключения»**. Адрес подставится из `config.json`.
2. Вставьте пароль команды, впишите своё имя (оно попадёт в журнал) и нажмите **«Подключить и проверить»**. Должно появиться «Подключено».
3. Первое подключение загружает в таблицу пример приглашения и общие блоки клуба.

**Остальным сотрудникам** дайте ссылку на сервис и пароль команды. Они делают шаг 7. Доступ к самой таблице им не нужен, но если хотите, чтобы они видели заявки прямо в таблице, откройте им её через **«Поделиться»**.

**Если меняете код `Code.gs`:** Развернуть → Управление развертываниями → карандаш → Версия: **«Новая версия»** → **Развернуть**. Адрес не меняется.

### Что лежит в таблице
- **Заявки**: дата, имя и контакт кандидата, о себе, кто рекомендовал, статус, комментарий команды. Статус и комментарий можно менять и здесь, и в разделе «Заявки» сервиса.
- **Приглашения**: список приглашений со статусом и версией. Сами приглашения лежат файлами в папке «Noôdome · данные приглашений» на вашем Google Диске. Папку не переименовывайте и файлы не удаляйте.
- **Журнал**: время, кто, что сделал. Частые правки одного и того же сливаются в одну запись.

### Безопасность
- **Пароль команды один на всех.** Если сотрудник ушёл, смените значение `TEAM_TOKEN` в свойствах скрипта: у остальных сервис попросит ввести новый пароль.
- **Адрес `/exec` виден всем**, потому что лежит в публичном `config.json`. Без пароля им можно только открыть согласованную страницу и отправить заявку. Приглашения в черновиках, интервью и заметки без пароля недоступны.
- **Заявки открыты всем отправителям.** От спама есть простая защита: не больше 40 заявок в минуту и ловушка для роботов.
- **Персональные данные.** В таблице лежат имена и контакты кандидатов, а в файлах приглашений тексты интервью. Доступ есть у вас и у тех, кому вы откроете таблицу и папку на Диске.

### Связка с CRM (в будущем)
Заявки собираются в таблице, поэтому подключить CRM можно без переделки сервиса:
- **Без кода**: Zapier, Make или n8n с триггером «новая строка в Google-таблице» и действием «создать контакт или сделку» в вашей CRM.
- **Из скрипта**: в функцию `submitLead_` в `Code.gs` добавить вызов `UrlFetchApp.fetch(адрес-вебхука-CRM, …)` после записи строки.

## 4. Как опубликовать новое приглашение

**С общим хранилищем (рекомендуется):**
1. **Новое** → материалы → **«Сгенерировать»** → проверьте блоки, вкладку **«Проверка»** и фото.
2. Согласуйте страницу с участником и нажмите **«Согласовано»**. Пока приглашение в черновике, ссылка показывает «Приглашение не найдено».
3. Вверху редактора нажмите **«Скопировать ссылку»**: в буфере окажется адрес вида `…/p.html?ref=anna-petrova`. Он же уже подставлен в готовое сообщение (**⋯ → Текст для мессенджера**). Отправьте участнику.
4. Дальше правки в сервисе сразу видны по ссылке. Ничего загружать на GitHub не нужно.
5. Чтобы убрать страницу, верните статус **«Черновик»** или удалите приглашение.

**Без хранилища (запасной вариант):**
1. Нажмите **«Скачать лендинг»**: скачается файл `anna-petrova.html`.
2. На GitHub откройте папку `i` → **Add file → Upload files**, перетащите файл → **Commit changes**.
3. Через минуту страница открывается по адресу `…/i/anna-petrova.html`. Чтобы поправить, скачайте и загрузите файл с тем же именем.

## 5. Общие блоки и афиша

- Раздел **«Клуб: общие блоки»**. Там меняются:
  - тексты «Что такое Noôdome» и «Сообщество»;
  - амбассадоры и их фото;
  - мероприятия: картинка, дата, рубрика, название, ссылка;
  - шаги и форма.
- Кнопка **«Вернуть исходные»** возвращает тексты и фото по умолчанию из `src/data/club.json`.
- **С хранилищем:** правка общих блоков сразу видна во всех приглашениях по ссылке, ничего скачивать не нужно.
- **Без хранилища:** каждый скачанный лендинг это файл со своей копией общих блоков. После правки афиши выложенные файлы сами не обновятся: скачайте их заново и загрузите в `i/`.
- В афише сейчас стоят 5 мероприятий ноября 2026 с noodome.club/events. Это пример. Актуальные события участнику можно присылать лично.

## 6. Где хранятся данные и как работать вдвоём

- **С подключённым хранилищем** приглашения, общие блоки и заявки лежат в вашем Google-аккаунте (таблица и папка на Диске). Браузер хранит копию и сам отправляет правки.
- **Если связи нет**, правки сохраняются в браузере и уходят на сервер при следующем подключении.
- **Что видит коллега.** Правки появляются у него при открытии раздела или не позже чем через 45 секунд. Журнал на странице «Приглашения» показывает, кто что менял.
- **Если правите одно и то же одновременно**, второй получит предупреждение и выберет, чья версия остаётся: коллеги или его.
- **Резервная копия.** Слева **«Сохранить всё в файл»**. Файл не кладите в репозиторий: в нём интервью и заметки.
- **Без хранилища** данные живут только в браузере каждого сотрудника, а передавать работу можно файлом.
- **Ключ ИИ и пароль команды** хранятся только в браузере сотрудника.

## 7. Важно про публичность

- Публичный репозиторий видят все: код, `index.html` (в нём пример Михаила вместе с текстом интервью), `config.json` с адресом хранилища и файлы в `i/`.
  - Перед настоящей работой удалите пример Михаила из `src/data/mikhail-tikhomirov.seed.json` и пересоберите `index.html` или замените пример вымышленным.
  - Кладите в `i/` только согласованные с участником страницы.
  - В публичную страницу попадают только тексты и фото самого приглашения. Интервью, заметки и вопросы для проверки наружу не отдаются ни в скачанном файле, ни по ссылке.
  - Новые интервью хранятся в вашем Google Диске, а не в репозитории.
- Страницы закрыты от поисковиков (`noindex`), но открываются у любого, у кого есть ссылка.
- Если репозиторий должен быть закрытым, для Pages нужен платный план GitHub. Сами страницы при этом всё равно открываются по ссылке.

## 8. Заявки кандидатов

- **С подключённым хранилищем** форма на странице сразу пишет заявку в таблицу (вкладка «Заявки»). В сервисе, в разделе **«Заявки»**, у каждой заявки есть статус и комментарий, их видит вся команда.
- **Без хранилища** кандидат получает готовый текст заявки и сам отправляет его на customers@nd.club.
- В скачанные лендинги адрес хранилища подставляется автоматически, поэтому и с файлов заявки идут в таблицу. Скачайте их заново после подключения.

## 9. Свой адрес вместо github.io (по желанию)

1. **Settings → Pages → Custom domain**: например, `invite.noodome.club`.
2. У того, кто управляет DNS домена, добавьте запись `CNAME invite → ИМЯ-АККАУНТА.github.io`.
3. Через 10–30 минут включите **Enforce HTTPS**.

## 10. Если меняете код

1. Правьте файлы в `src/`.
2. Выполните `python3 src/build.py` из корня репозитория. Обновятся `index.html` и `p.html`.
3. Загрузите `index.html`, `p.html` и изменённые файлы на GitHub. Код `backend/Code.gs` обновляется отдельно в Apps Script.

Хотите, чтобы у всех обновились общие блоки по умолчанию? Поменяйте `src/data/club.json` и увеличьте в нём `"version"` на 1. Тогда при следующем открытии сервиса общие блоки обновятся у всех. Правки, которые человек сделал у себя в разделе «Клуб», при этом заменятся.
